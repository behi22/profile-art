# profile-art

The animated images on my GitHub profile, [github.com/behi22](https://github.com/behi22).

Every image is redrawn every hour from live data: the real time and sky over Vancouver, tonight's moon, whether it's actually raining, my contributions from both of my accounts, and 21 holidays that each change the scenes. Nothing on the profile is updated by hand.

**See the current hour:** [behi22.github.io/profile-art](https://behi22.github.io/profile-art/)

Everything below is a small detail you might miss, section by section.

## 2. Say my name

<picture><source media="(prefers-color-scheme: dark)" srcset="https://behi22.github.io/profile-art/say-my-name-dark.svg"><img src="https://behi22.github.io/profile-art/say-my-name-light.svg" alt="How to say Behbod Babai, as one voice agent turn"></picture>

One real voice-agent turn, stage by stage, in 12 seconds:

- **Mic:** "How do I say your name?" comes in as a waveform, one burst per word.
- **Voice activity detection:** it shows speech, then a 500 ms silence ring fills and ends the turn.
- **Speech to text:** partial transcripts turn into the final one.
- **LLM:** it thinks, then streams 12 tokens.
- **Text to speech and speaker:** five syllables play, and the speaker thumps and rings on each one.
- Small packets of light travel between the stages on the same clock, and each stage shows a realistic latency: about 200 ms for speech to text, 400 ms to the first token and 250 ms to the first audio.

The answer underneath:

- My name is spelled out letter by letter into slots.
- The syllables get a bouncing dot that lands on each one as the speaker says it.
- My name in Persian, بهبد بابایی, is written right to left behind a sliding shutter with a pen nib on its edge.

## 4. About and links

<picture><source media="(prefers-color-scheme: dark)" srcset="https://behi22.github.io/profile-art/about-dark.svg"><img src="https://behi22.github.io/profile-art/about-light.svg" alt="About Behbod Babai, as a terminal"></picture>

- It types itself out in order: `echo "Hello, World"`, `whoami`, `whereis`, my specialty, `ls experience/`, three running `jobs`, my interests, my motto and `ls links/`, then it waits on a blinking cursor.
- `ls links/` lists the five link cards underneath. Each card is its own image, so each one is a real link.
- The terminal and the cards share the same edges and the same gap between each, on any screen. Phones place a short image on a text line taller than itself, so the profile README aligns each card to the bottom of its line and the spare space lands above every card, the first one included. - The work line's "1,000+ contributions" is worked out from live data and rounded down, so it's always true.

When two holidays overlap, the one higher in this list wins, with two exceptions:

- Cherry blossom season waits until Nowruz and Sizdah Bedar are over.
- When Chaharshanbe Suri lands on Pi Day (2028, 2034, 2045), Pi Day has the day and Suri takes the evening from 5 PM.

The date rules:

- Nowruz uses the astronomical rule: the year starts on the day of the March equinox if it falls before noon in Tehran, otherwise the next day.
- Lunar New Year uses the official dates through 2050.
- The Celebration of Light uses a fixed late-July window, because its exact nights are announced each year.

## How it works

- **No scripts:** every image is a single self-contained SVG, with no JavaScript and nothing loaded from elsewhere. All the motion is CSS and SVG animation, which is what GitHub allows inside a README.
- **Light and dark:** each image comes in both, and the README picks one with `<picture>` to match your GitHub theme.
- **Reduced motion:** with reduced motion turned on, most of the motion stops and each image settles on a finished frame.
- **Every hour,** a GitHub Action (`.github/workflows/render.yml`) does four things:
  1. Fetches both accounts' contribution calendars from GitHub, and the current Vancouver weather from [Open-Meteo](https://open-meteo.com).
  2. Draws all 38 images for this hour.
  3. Checks every image: well-formed, no broken numbers or references, nothing loaded from outside, within size.
  4. Publishes them to GitHub Pages.
- **If a check fails,** nothing is published and the profile keeps the last good hour.
- **If a data source is down,** the run uses the last good copy (or a dry sky for the weather), so a bad hour never breaks the profile.
- **Tests:** every code change runs the full suite before anything is published. It is about 44,000 renders:
  - every hour on 22 dates through the year (both solstices, the equinoxes, New Year's and a leap day)
  - in dry weather, light rain and heavy rain, in light and dark
  - every day of every holiday for three years, and the holiday rules out to 2050
  - sunrise and sunset against published times
  - bad inputs: odd weather values, missing weather, empty and spiky contribution data
  - the terminal and its link cards lining up as one column
- **Time zone:** British Columbia stays on daylight time all year from 2026, so the clocks no longer fall back in November. The images follow that through the system's time zone data, and the render refuses to run on time zone data too old to know it.

### Run it locally

Needs Node 24 or newer.

```
npm test         # the full test suite
npm run build    # fetch this hour's data and draw everything into dist/
```

`npm run build` needs a `GITHUB_TOKEN` in the environment to read the contribution calendars. Without one it falls back to the last published data. To draw a specific moment, set `RENDER_AT`, for example `RENDER_AT=2026-10-31T05:00:00Z npm run render`.

### Files

- `src/engine.js`, `src/helpers.js`: drawing basics (shapes, letters, colours, the SVG wrapper)
- `src/live.js`: the Vancouver clock, the sun and moon, the seasons and the 21 holidays
- `src/sections/`: one file per section
- `scripts/fetch.js`, `scripts/render.js`, `scripts/check.js`: the hourly run
- `scripts/qa.js`: the test suite
- `data/sample-contrib.json`: a year of real data, used by the tests and as the last fallback
